# Project Context — Read This First

This folder is the onboarding brief for any agent (or human) picking up work on **Rhazes Labs**. Read these files before making design or content decisions:

1. **[product.md](./product.md)** — what this site is, who it's for, and the three goals it serves
2. **[design-system.md](./design-system.md)** — colors, typography, components, and the Apple-style principles this site follows
3. **[content-guidelines.md](./content-guidelines.md)** — the authenticity rules: no fabricated data, no stray company names, no em dashes
4. **[architecture.md](./architecture.md)** — tech stack, data model, and patterns specific to this codebase

## The single most important rule

**Never invent content.** Every fact on this site (projects, experience, testimonials, metrics) must come from the owner's real LinkedIn, real client work, or explicit instruction. When in doubt, ask rather than fill a gap with something plausible-sounding. This has been the guiding rule through every content pass on this project — testimonials, projects, and experience were all rebuilt from real data after starting from generic placeholders.
